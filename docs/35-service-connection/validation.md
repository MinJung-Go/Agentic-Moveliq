## 当前实施范围

用户于2026-10-18明确回复“按第二版接入”，已按该版实施原生页面。初稿未获确认；第二版采用 Milo 欢迎区与底部连接卡，两列服务选择、当前项进度和精简结果替代长列表。OnboardingView首次登录主动展示，复用RootView原账号引导完成键，跳过/完成后不反复弹出，普通升级保持原状态；CoachPluginsView作为同一页面的设置补连入口。

NativeServiceConnection连接Calendar/AlarmKit/MusicKit/CoreLocation及原健康授权，串行等待App活跃状态，全局防重叠请求。ServiceConnectionModel核对账号、保存选择后再请求系统授权，拒绝后继续，支持暂停、后台/页面退出停止、回前台状态复查。日历范围/默认写入位置缺失时引导补充，不代选；保留已有训练同步与自动调整规则。准备版本0.5.19（40），原生编译/单测尚待CI。

健康开关以可选字段保存在账号SwiftData配置：旧JSON缺字段保持原行为，新账号首次跳过明确关闭，防止继承设备上其他账号的读取接入。关闭后停止后续导入，已保存记录保留；异步查询返回后再次核对账号代次和开关才落库。旧设置页的显式授权/同步可以重新开启连接。

独立的非 UI 源码新增 `ServiceConnectionFlow`：仅处理选定目标，串行等待、重新检查系统快照、已授权/被拒绝/受限/不可用不重新弹窗；单项拒绝/失败可继续其余服务。请求前、恢复活跃后、系统返回后复查账号及批次；停止保留已处理结果，原请求未返回时禁止再次启动，晚到结果不覆盖新批次。健康选择完成与完整授权状态分开，不选择日历或修改训练同步规则。
