# 首页与分析报告可读性

## 背景与目标

用户反馈首页图文混排显得杂乱、饮食记录的相机图标和“AI 估算”标签未对齐，并提供分析报告整段正文的截图。本轮设计稿已完成；2026-10-15 用户回复“开发吧”，确认按当前稿接入 App。沿用 Moveliq 暖橙品牌、现有 Milo 资产、首页模块顺序与既有业务。

## 范围

### R1 首页分组与间距

- 减少等权重白卡：首页使用统一浅色底，课程作为主要行动容器，记录为轻量列表，身体状态为折叠行。用分组标题、留白和分隔线建立层级，不给每段内容都加卡片；仅调整本轮页面，不修改聊天正文或全局主题语义。
- 日期降为辅助信息，问候不强制换成两行；Milo 与问候组成紧凑整体，移除重复的自我介绍，保留两个轻量快捷对话，让课程和记录更靠前。统一左右边距、分组标题与必要卡面的内边距。
- 保留问候、Milo 小头像、两个快捷对话、今日课程、近期三条记录、身体状态折叠区、照片/文字/语音输入及五个 Tab。无计划、有计划、休息日、空记录均沿用真实状态，不编造数据。

### R2 紧凑记录列表与对齐

- 记录使用无外层卡片的紧凑列表：左侧类型图标，中间名称与摘要，右侧固定信息列展示时间与来源状态。普通短记录不固定增加第三行。
- 照片小图标在左侧类型图标下方使用独立对齐基准；“AI 估算”降为右列次级文字，与时间统一靠右，不再作为醒目的胶囊标签重复出现。无照片时不显示相机，状态为空时不显示占位文案。
- 首页优先展示已有结构化食物名称，包装/解释等完整描述留在详情。不能安全精简时保留原名并允许两行；不凭空生成新名称，不丢原文或改写持久化内容。
- 时间采用等宽数字，摘要、待归类状态与 HealthKit 来源/只读信息保留。右列不与标题争抢同一行的可变宽度。
- 共享 RecordRow 同时影响首页和记录页：实施时两处一起验证，不加载原始照片替代轻量 hasPhoto 标记。
- 窄屏和大字体允许摘要、长标题与状态自适应换行，优先可读性，不锁死行高或用空格凑齐。

### R3 分析报告排版

- 按“统计区间与来源 → 一句话结论与轻量状态 → 分段正文 → AI 依据 → 原有说明”组织内容；报告采用连续阅读页面，移除包裹全文的大卡片及重复的“详细分析”标题。
- 保留全部 headline、body、tags、citedDataText；不截断报告，不改写已经生成的分析结论，不从正文拼凑图表或推断新指标。
- 正文使用适度行距与明确段间距，扩大有效阅读宽度。已有换行优先保留；历史无换行长正文可按完整句子做展示分段，不截断数字、小数、单位或句子，不修改持久化原文。
- 继续使用现有报告数据结构与生成协议；本轮不新增模型调用、服务接口、SwiftData 迁移或分析算法。AI 依据继续默认折叠，可展开核对。

### R4 统一消息输入栏

- 本轮追加首页、Milo/课程教练共用聊天页、“记一笔”三处输入栏统一设计。统一消息输入组件，不扩展到登录、搜索、表单等不同用途字段。
- 同一套中性填充容器，基准高度 52pt、左右外边距 16pt、正文字号 17pt，所有图标触控区域至少 44pt。正文支持 1–4 行增长，超过后内部滚动，不横向挤压操作按钮。
- 左侧“＋”承载当前入口已有操作：首页与记一笔为选照片；Milo/课程教练为实时通话。教练不展示尚未支持的照片功能；实时通话与语音转文字是两个独立操作，不混淆。
- 空内容右侧为麦克风；有文字或附件后显示暖橙发送按钮，并保留独立语音输入入口，可向已有草稿补充转写。聚焦时提供统一收起键盘操作，草稿和附件不丢。
- 语音只转文字，不自动发送；结束后可编辑，取消恢复录音前草稿。首页麦克风当前会打开记一笔，正式开发时需将其改为原地转文字，并复用既有 VoiceInput 行为；该交互随本轮设计获准实施。
- 附件在输入栏上方以同一轻量样式展示，可移除；只有照片时也能发送，选择照片不自动提交。
- 忙碌时禁止重复提交。教练生成中保留“停止生成”；首页处理和记录解析只显示进度，不捏造尚不存在的取消能力。状态与权限错误提示位于输入栏上方，不清空草稿。
- 本地稿补充三入口同屏对照，以及空白、文字、多行、附图、语音、忙碌、失败、键盘等状态。后续实施应提取共享 SwiftUI 输入组件和按入口注入的操作，避免复制三套样式。

### R5 统一基础组件

- 本轮追加基础组件设计：主按钮、来源标注、亮色图标前景、加载/禁用反馈、小操作触控范围和表单字段；在现有交互稿增加组件对照，不新增独立稿件或局部截图。
- 主按钮以多数现有页面的 PrimaryButtonStyle 为基准：12pt 圆角、暖橙底配 onAccent 深字、17pt 半粗体、基准最小高度 50pt；确认应用修改与开始训练使用同一外观。发送按钮保留圆形；次按钮/文字动作至少 44pt，破坏性操作保持红色语义及既有系统确认。
- 正常、加载、禁用、按下反馈使用同一组件；加载指示器继承当前前景色，避免固定白点落在浅色禁用背景。仅加载状态显示进度，不赋予业务尚不支持的取消能力。
- “AI 估算”统一为次级来源标注，列表与详情使用同一字色，不再切换白字/黑字亮底标签。待归类、错误、只读保留各自含义；不把来源全部当成警告。
- 暖橙底图标使用 onAccent 深色，分类颜色仍按语义使用合适前景。普通小图标视觉尺寸可小于 44pt，但其操作范围不少于 44pt。
- 表单字段自身统一为 12pt 内嵌圆角、17pt 输入字号及关联标签/错误提示，不套用消息胶囊。搜索、系统 Form、系统确认框和通话控制继续保留适合场景的形态。
- 修正既有设计系统与实际 Theme 的明显矛盾，并将“当前实现基线”与第 33 轮已确认的组件应用范围分开。按已确认稿修复 SwiftUI 调用，验证结果另行记录。

## 验收

- 浅/深色、320/390/430 逻辑宽度和大字体下，无文字与图片重叠、时间裁切、标签挤压标题或横向溢出。
- 截图中的两条饮食记录：两种标题长度下时间/估算状态右边缘一致，照片图标有固定的左侧列，不随标题漂移；常规字体下两条记录和课程可在 390pt 首页首屏辨认。
- 没计划/有计划/空记录、长标题/无照片/无标签/只读记录均有设计示意，触控目标至少 44pt。
- 报告旧数据无需重新生成即可阅读；正文完整、AI 依据可展开；无数据时不生成装饰图表或虚构指标。
- 设计预览与实际 SwiftUI/CI/真机验证分开记录。本次授权实施 App；提交/push 和 IPA 需另获明确授权。

## 根因初查

- TodayView 使用 conversationCanvas（浅色白色），card() 同样使用白色卡面；白底下模块边界消失。
- RecordRow 将标题、相机和 Badge 放入同一个 HStack，整组宽度随标题变化，标签没有独立对齐基准。
- ReportDetailView 直接把 report.body 交给 MarkdownText；没有换行的历史正文会渲染为一个长段落，难以扫读。
