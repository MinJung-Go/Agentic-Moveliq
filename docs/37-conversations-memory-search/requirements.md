## R1 · 会话组件

- 在聊天顶部明确提供会话入口；会话面板内提供新建、搜索、按日期分组的列表和当前会话标记。
- 2026-10-23 设计反馈：用户认为第一版新建界面不好看，要求参考豆包。第二版采用居中导航标题与右上角写字图标新建，移除大色块新建按钮、页面大标题和宣传副标题；点击直接进入空白聊天页，底部保留统一输入栏及语音输入。参考的是公开手机截图的入口结构，不声称精确复刻当前豆包 iOS 版本。
- 最新会话设计见 [第二版三屏流程](design.conversations.html)，包含会话列表、新建空态与继续聊天。用户已于 2026-10-23 确认接入。
- 第二版补充：用户指出聊天页右上角只有电话。会话列表与聊天页均须直接提供新建；聊天页右上角并列“写字图标＝新建对话”和“电话图标＝实时通话”，各保留 44 pt 触控区域，不要求返回列表才能新建。
- 行内主信息为标题，辅助信息为最后消息摘要与时间；空标题使用“新的对话”，不显示空白行。
- 新建不清空旧会话，不重复生成多个未发送的空会话；切换后显示对应消息。
- 待发送文字／附件仍属于原会话，切换不丢失；生成中及实时通话中阻止切换，并说明原因。待确认操作不能带到其他会话执行。
- 删除需确认：删除会话默认保留已保存的个人资料、记忆与技能；删除当前会话后回到有效会话或新对话。
- 验收：新建、切换、搜索无结果、删除当前会话、生成中、草稿恢复、账号切换均有明确结果。

## R2 · 个人资料与记忆

参考仓库的有效个人字段为以下五类；不是复制该项目的企业／产品档案。

| 稳定字段 | 页面名称 | 内容边界 |
| --- | --- | --- |
| name | 姓名 | 用户主动提供，不从登录名或第三方资料推断 |
| nickname | 称呼 | 用户希望 Milo 如何称呼自己 |
| timezone | 时区 | 有明确依据的 IANA 时区；未知时未填写，不悄悄改变提醒调度 |
| background | 关于我 | 稳定的身份与日常背景，不混入临时事件或条件化方法 |
| preferences | 我的偏好 | 稳定的沟通与个人偏好；“遇到 X 做 Y”归入技能 |

- 管理页分为“资料／记忆／技能”，默认资料；资料按字段阅读与修改，记忆和技能保持轻量列表与详情。
- 未填写字段显示“未填写”，不让模型补全。多行内容可编辑；来源和修改记录折叠展示。
- Agent 通过现有工具执行局部 patch；提交后从持久化结果读回，回执仅包含实际保存的字段。相同内容不重复写版本或通知。
- 资料、记忆和技能保留编辑、删除、来源、版本与撤销；技能保留停用、归档。历史整理、导入导出入口收在管理菜单内。
- 旧画像不因结构化改版丢失：只有能够确定的条目映射到字段；无法识别／冲突条目保留在“其他已保存资料”，可由用户整理。原 ID、来源、历史保持可追溯。
- 现有训练与日常设置继续使用原数据源，提供入口，不复制一套可互相覆盖的训练字段。
- SwiftData 仍是唯一数据源，`USER.md` 是可读导出视图，不增加另一份可独立写入的配置文件。
- 验收：在对话中说“叫我小林”，工具保存后新会话、详情和导出一致；修改偏好不覆盖姓名；删除、撤销、导入、迁移与重启后读回一致；他人网页信息不能写成用户画像。

## R3 · 通用网页搜索与正文读取

- 支持公共查询词，不再限制七个健身主题，也不强制给每条搜索词附加 `site:`。
- 健康问题优先呈现相关指南、研究及专业机构来源；“优先”不等于站点白名单，也不意味着网站内所有内容均可信。
- 浏览与供 Milo 使用的结果／正文读取分开。用户仍可查看网页；无法提取时保留浏览入口，不自动关闭或声称已读到正文。
- 沿用此前方向：App 内 Safari 负责浏览；独立检索／读取通道向 Milo 返回来源，不尝试从 Safari 获取 DOM。具体通道见方案；没有已验证可用的通道不能标记修复完成。
- 区分：加载中、有结果、确实无结果、需验证、网页可见但提取失败、网络错误、用户取消。页面结构变化不得伪装成“没有搜索结果”。
- 来源须包含标题、真实 URL、可用摘要及检索标识；读取正文结果独立标记，模型不能把搜索摘要当已阅读正文。
- 公开查询最小化，不自动加入姓名、账号、个人档案、原始健康数据或完整对话。识别到敏感内容先在本地澄清或改写，不擅自提交搜索引擎。
- 通用访问仍限制为公开网页：禁止凭据 URL、本地／内网目标及危险协议；逐跳校验。网页内容始终是不可信引用，不能授予工具权限或修改画像。
- 不默认引入收费搜索 API；不通过本轮默默部署新的后端服务。若现有抓取通道在目标地区不可靠，记录证据和候选替代方案后明确决定。
- 验收：普通非健康查询能获取不在旧白名单中的来源；健康查询有来源优先级；验证码／DOM 变化／网络错误不会误报成功；网页停留、返回聊天、重试、取消和连续两次查询不串结果。

## R4 · 跨页面颜色统一

- 覆盖首页、记录及详情、课程及详情、洞察及报告、设置及子页、聊天、会话、记忆、搜索容器和编辑弹层。
- 同一语义使用同一 token：页面底、分组底、输入底、主文字、次要文字、辅助文字、分隔线、操作色；浅深色成对维护。
- 以第 33 轮已使用的暖白／暖灰为提案基线，消除白、蓝灰、暖灰混用；导航、底栏、列表默认背景也纳入检查。
- 分类与状态颜色保留含义：成功／错误／训练等不能全部涂成强调色；相机、视频、照片预览可保留黑色沉浸背景；第三方网页和系统授权页面不强行改色。
- 设计稿先展示统一配色与页面预览。确认后将 token 收敛为全局语义接口，旧 `Theme.Journal` 通过兼容别名过渡，不新建第二套配色。
- 验收：跨五个主 Tab 与聊天／记忆跳转不突变底色；浅深色、大字号、提高对比度、键盘弹出与滚动状态检查。常规文字对比度目标 ≥4.5:1，必要控件边界／焦点 ≥3:1。
