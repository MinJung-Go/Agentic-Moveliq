## 目标

用户可以新建、切换会话，仍与同一个了解自己的 Milo 交流。Milo 从交流和任务处理中积累个人资料、长期记忆和可复用的方法，并在相关任务中按需搜索和使用。

本轮先实现个人技能的积累与使用，不预装健身技能，不搜索外部技能市场。文中的 Skill 搜索始终指当前账号自己的技能库。

## 功能需求与验收

### R1 · 分清资料、记忆、技能和会话状态

- USER 保存个人资料与稳定偏好；MEMORY 索引长期事实、决定和经验；Skill 保存适用条件、可复用步骤及注意事项。
- 临时状态须保留时间与适用范围，不能直接转成永久偏好；当前会话的待确认操作不能因另一会话加载技能而自动执行。
- USER／MEMORY 自动整理，提供查看、编辑、删除入口；重要变化简短通知。
- 验收：新会话可以按需找到此前保存的方法；能够区分“只有哑铃”“今天加班”和“加班时如何调整训练”。

### R2 · 自动抽取与候选

- 用户明确要求保存一个方法时，进入直接保存流程，记录来源，成功后通知并允许撤销。不能以未重复出现或未得到效果反馈为由跳过明确保存请求；信息缺失或写入失败需如实说明。
- 主动抽取不以用户发出保存指令为前提。只有 AI 提出、尚无执行结果或用户反馈的方法先内部留作候选，不作为正式技能自动使用。
- 有执行结果、后续反馈或重复证据后，再评估是否可复用并自动入库。重复证据不能只来自模型重述自己的建议。
- 保留来源与证据类型；区分“工具操作完成”“用户认可方法”和“实际效果得到反馈”，不把其中一种伪装成另一种。
- 默认处理启用后的新对话；另提供手动整理历史会话的入口。
- 验收：未验证建议不会直接成为正式技能；用户要求保存时有持久化结果；历史整理不自动扫描所有旧会话，重复整理不重复建同一技能。

### R3 · Skill 工具与检索

- 向 Milo 提供统一的 Skill 工具，支持技能库内搜索、按标识加载和维护。具体 action 名称及 schema 在技术设计中确定。
- 搜索先返回匹配技能的简要信息，选中后再加载正文；不把全部技能正文塞进每次请求。
- 查询与加载仅限当前账号，默认排除内部候选、停用、归档及已删除技能。
- 技能负责提供方法，现有业务工具执行操作；技能文本不能创建或扩大自动执行权限。
- 验收：会话 A 保存的方法可在会话 B 中找到；没有匹配项时正常完成对话；加载技能不能绕过课程修改等既有授权规则。

### R4 · 去重、更新与撤销

- 入库前搜索相似技能：明确纠正则更新；适用条件不同则补充分支；含糊或冲突无法判断时询问。
- 已有 Skill 的内容修改采用 `patch` 局部补丁，不提供整篇覆盖的 `update` 接口。先读取当前内容与版本，再提交明确的修改范围；版本不符或目标片段匹配不唯一时拒绝修改，重新读取后再生成补丁。前台与后台共用此规则，不能通过保存接口覆盖已有技能。
- 保留旧版本，支持撤销更新。撤销保存须撤回对应新增或更新，不能误撤后来独立发生的编辑。
- “这次不用／这次别这样”仅影响当前任务；明确表示“以后别这样”时才更新或停用相应技能。
- 长期未使用的技能不自动删除或归档；通过搜索按需使用，允许用户手动归档和恢复。
- 验收：相同方法重复出现不无限新增；条件分支不会直接覆盖原有适用场景；当前任务拒用不改变技能的长期状态。

### R5 · 用户管理与会话删除

- 技能提供轻量列表、详情，以及编辑、停用、删除、归档和恢复操作；资料与记忆同样可查看、编辑、删除。
- 删除会话默认只删除会话，保留已保存的个人资料、记忆和技能；删除提示需明确说明这个行为，并给出管理入口。
- 原会话删除后，关联项不得声称仍可打开原会话。来源证据保留到什么粒度，在技术设计中明确，避免为保留技能而隐式备份完整会话。
- 验收：删除来源会话后技能仍可使用；删除某条记忆或技能后不再被正常检索到；不同账号之间不可互见。

### R6 · 本机存储与导入导出

- 第一版数据保存在本机，提供手动导出、导入。换设备不会自动同步，需用户主动迁移文件。
- USER.md／MEMORY.md 为可读视图；实现遵守 SwiftData 唯一数据源约定，避免文件和数据库分别可写造成冲突。
- 导出不得包含登录会话、供应商 Key 或账号密码。导入的内容不能带入原设备的自动执行授权，也不能作为程序或脚本执行。
- 导出采用版本化 JSON，包含正式条目及内容版本；候选、任务队列、完整会话和执行授权不导出。同 ID 同内容跳过，冲突先预览选择，跨账号需明确确认。此文件不是整套 App 备份。
- 验收：规定范围内的数据可导出后恢复，导入失败不破坏已有数据；账号切换或退出时后台处理不能写入其他账号。

## 追加需求 · App 内 Safari（2026-10-23）

- 用户要求在当前 `feat/personal-agent-skills` 分支追加，明确指 Safari 网页浏览，不是 Siri。
- 默认 websearch 通过 App 内 Safari 界面展示搜索页，网页链接也在 App 内打开。
- 技术边界：`SFSafariViewController` 提供系统浏览界面，不向 App 暴露页面正文、搜索结果或浏览过程。不能直接替换当前 `WKWebView` 抽取后仍声称 Milo 已获得网页内容；Safari 本身也不是搜索引擎。
- 用户已确认：Safari 负责浏览，独立搜索／正文读取通道供 Milo 获取资料并继续回答。不能把打开网页当成取得正文，也不能直接读取 Safari 内的页面。
- 用户补充出发点：现有内置浏览器搜索一直失败。先排查并修复现有搜索链路，再接入 Safari；此次非 UI 缺陷修复不改变已确认页面。
- 已复现：`searchURL` 的站点分组带有字面括号，`allows` 拒绝字面括号，7 个公共主题均在网络加载之前被拦截。应编码查询参数中的括号，保持解码后的查询及站点限制不变，不放宽来源校验。
- 缺陷验收：全部主题生成的地址通过同一入口校验；查询条件完整往返；非 HTTPS、未知站点、凭据、异常端口和字面危险字符继续拒绝。Linux Foundation 检查不代替 iPhone 网页加载、验证页及实际内容提取测试。
- Safari 新交互尚未确认／接入。现有 App 与 Service 保留搜索／阅读接口，但服务开关、供应商权限和调用成本需在方案中明确，不能在修复浏览器失败时静默切到付费接口。
- 技术参考：[Apple SFSafariViewController](https://developer.apple.com/documentation/safariservices/sfsafariviewcontroller)。

## 0.5.20 真机反馈追加（2026-10-23）

- 联网搜索：用户确认新版搜索页闪现后立即退出。检查发现 `WKContentRuleList` 使用多域名 `|` 正则，WebKit 规则解析器拒绝 disjunction，随后错误路径调用 finish 关闭页面。改为每域名单独规则，保留来源边界；加入真实 WebKit 规则编译测试。Bing 中国域名搜索页和跳转链接也需正确识别，不误当正文。
- 记忆反馈：同一条「已记住／已更新」一直停在聊天底部，不是用户确认的连续重复写入。现实现固定显示最近 3 条未撤销通知，需调整呈现，不以撤销保存作为关闭通知的手段。
- 能力说明：用户说姓名后，聊天说没有存储位置，后台却保存到个人资料。聊天工具读写权限与后台自动整理能力需准确说明；只有实际写入成功才能声称已持久化。
- 抽取失败：尚无具体错误原文，保留排查项；不能把上述常驻通知或联网搜索错误当作抽取失败根因。
- 用户要求在当前分支优化设置中的「Milo 的记忆」UI。[优化预览](design.memory.html) 展示资料／记忆／技能切换、内容优先的列表、正文详情与折叠来源、轻量编辑。新版原生页面待设计确认；保持管理、来源、版本、撤销、历史整理与迁移功能范围。
- 保存提示可以单独收起，不删除或撤销已保存内容；新用户消息后不再固定显示更早提示。旧数据须兼容新增的提示收起状态。
- WebKit 规则限制依据：[URLFilterParser 源码](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/contentextensions/URLFilterParser.cpp) 的 disjunction 处理明确失败；Foundation 正则测试不能代替真实 WebKit 编译。

## 追加 · 对话内维护资料与记忆（2026-10-23，用户已确认开发）

- 首页 Milo 与课程 AI 教练通过现有 `skill` 工具的 `kind=profile|memory` 直接保存、更新用户画像和长期记忆；不要求用户先说“记住”，明确自述的稳定事实即可提案。保持 `kind=skill` 兼容。
- 姓名／称呼／稳定偏好归资料，长期决定与经验归记忆；临时状态、不确定推断和只有 AI 提出的内容不写为个人事实。训练配置沿用原入口，不复制或修改自动执行授权。
- 新建先搜索避免重复；更新必须先读取完整条目和版本，通过 patch 局部修改，不提供 update 整篇覆盖接口。资料的一句事实允许通过精确 patch 完整纠正，Skill 仍禁止整篇正文替换。
- 工具经来源核查、账号／版本检查和本机事务保存成功，返回条目 ID 与版本后，Agent 才能回复已记住／已更新。失败、冲突、取消不伪装成功，含糊时询问。
- 后台整理保留，用于遗漏补充与方法提炼；与前台使用同一维护器、去重、来源抑制及撤销规则，不另建一套存储。相同内容不重复产生通知。
- 本次仅调整工具与数据链路，沿用现有通知及管理页面；不包含尚未确认的新版页面布局，也不新增云端存储。
- 验收：明确姓名可经工具保存并在后续会话读取；纠正姓名以 patch 留历史且可撤销；类别不符、缺少读取、旧版本、伪造来源、助手猜测、撤销后同源重建均拒绝；后台遇到前台已存相同内容不重复建档。

## 非功能要求

- 自动抽取与维护不阻塞正常回复；中断、失败和重试应可恢复且避免重复入库。
- 检索与上下文加载须有预算，保留当前用户指令和相关限制。具体候选门槛、检索阈值与预算通过评测确定。
- 本机保存不等于本地模型推理：本轮不恢复本地模型，不承诺模型请求完全不出设备。新增抽取请求的数据边界需在技术设计中写清，沿用现有数据最小化约定。
- 模型建议、用户要求、执行回执与效果反馈需可区分，不能用模型自评替代实际证据。

## 细节追踪（已在实现记录明确，仍需原生验收）

- 页面入口、通知与撤销呈现；资料、记忆、技能的浏览及编辑方式。
- 历史整理的会话选择、进度、取消与失败重试。
- 删除／撤销后防止同一来源马上重新抽取；用户手动编辑与自动维护冲突处理。
- 候选晋升规则、失效时间、来源保留粒度、版本并发及导入导出协议。
